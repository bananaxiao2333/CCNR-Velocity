# 03 · 部署与运维

## 1. 安装

```bash
./scripts/check.sh
cp build/libs/ccnr-control-velocity-0.1.0.jar /path/to/velocity/plugins/
```

首次启动生成 `plugins/ccnr-control/config.properties`；填好 `endpoint` / `token` 后重启。

## 2. 上线顺序

1. CCNR-Data 先升级到含 `control.v1` 的版本，确认 `/healthz` 正常。
2. 插件先以 `fail-open=false`、只观察日志的方式跑一轮（拒绝会真的拦人，建议先在测试服）。
3. 确认 `ListOnlinePlayers` 与代理实际在线数一致。
4. 再打开正式准入。

## 3. 观测

代理日志关键字：

| 日志 | 含义 |
|---|---|
| `CCNR 控制面已连接` | 启动成功，含 endpoint / fail-open / 超时 |
| `拒绝 <玩家>：<原因>` | 准入拒绝；原因与 `AuthorizeReason` 一致 |
| `会话开始 / 转服 / 会话结束` | 生命周期；转服会打印 from → to |
| `遥测队列已满` | 控制面写入跟不上；看 CCNR-Data 与网络 |
| `遥测上报失败` | 单条失败（deadline / UNAVAILABLE / 业务错误） |
| `配置无效，插件停用` | 配置缺项或越界；插件不再拦截 |

服务端侧看 `/metrics` 的 `ccnr_control_authorize_total` 与 `ccnr_control_sessions_online`。

## 4. 排障

| 现象 | 先看 |
|---|---|
| 所有人都被拒 | `endpoint` / `token`；服务端是否 `UNAUTHENTICATED` |
| 部分人被拒 | 服务端拒绝原因；`NOT_LINKED` 表示未绑定，`BANNED` 看规则 |
| 在线数偏少 | 心跳是否在跑；服务端 `last_seen` 是否更新 |
| 在线数偏多 | 代理崩溃留下的会话；等 180 秒收尾或查 `SessionReaper` |
| 登录明显变慢 | 控制面 RTT；确认 deadline 是 1 秒而不是无限 |
| 统计缺事件 | 队列满日志；网络分区期间的丢事件是设计内行为 |

## 5. 回滚

删掉插件 jar 并重启代理即可回到无准入状态；CCNR-Data 中的数据保留，不影响模组数据面。
