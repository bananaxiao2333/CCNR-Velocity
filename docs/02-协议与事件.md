# 02 · 协议与事件

契约权威在 `src/main/proto/control/v1/control.proto`（与 CCNR-Data 同源）。

## 1. 登录（Device Code）

玩家先连 `auth`（limbo），插件调：

1. `BeginDeviceLogin(player_uuid, username, proxy_id)` → `login_id`、`user_code`、`verification_uri`；
2. 把 `verification_uri` 与 `user_code` 发给玩家；
3. 每 `interval` 秒调 `GetDeviceLoginStatus(login_id)`，直到 APPROVED / DENIED / EXPIRED；
4. APPROVED 后调 `AuthorizePlayer(player_uuid, username, lobby, proxy_id)` 做封禁/角色检查，通过才送 `lobby`。

授权与本条连接绑定：**每条连接都要重新完成一次 Pass 授权**，不信任跨连接缓存。

## 2. 准入

`AuthorizePlayer` 只读；拒绝由插件上报 `LOGIN_DENIED`。
它不再负责"证明你是谁"——那是设备码的职责，它只看封禁、白名单、邮箱与角色。

## 3. 事件

| kind | 何时 | 必填 | 服务端动作 |
|---|---|---|---|
| `SESSION_STARTED` | 首次 `ServerConnectedEvent` | session_id, uuid, username, server_id, proxy_id | 插入会话 |
| `SESSION_HEARTBEAT` | 每 60s | session_id | 只刷新 `last_seen_at` |
| `SERVER_SWITCHED` | 换服 | session_id, server_id, from_server_id | 更新 server_id |
| `SESSION_ENDED` | `DisconnectEvent` | session_id, end_reason | 写 ended_at |
| `LOGIN_DENIED` | 登录被拒 | player_uuid, deny_reason, server_id | 只写事件表 |

## 4. 幂等

- 每个事件一个 `request_id`（UUID）；**重试必须复用**。
- 心跳不占幂等键：它只做一次 UPDATE，天然幂等。
- 同 `request_id` 不同载荷会被服务端拒绝（`FAILED_PRECONDITION`），这是有意的。

## 5. 时间

- `occurred_at` 取本地 `Instant.now()`；服务端夹在 `[now-24h, now+5m]`。
- 服务端在响应里回 `server_time`，排障时可对比时钟偏移。

## 6. 在线判定

服务端口径：`ended_at IS NULL AND last_seen_at >= now - 180s`。
因此心跳间隔必须明显小于 180 秒（默认 60）；代理崩溃后会话最多 180 秒后不再算在线。
