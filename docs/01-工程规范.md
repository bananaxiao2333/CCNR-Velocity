# 01 · 工程规范

## 1. 语言与依赖

- Java 17 源码 / 字节码；Gradle wrapper 固定 9.8.2。
- Velocity API 固定 **3.4.0 发行版**，不用 SNAPSHOT。
- gRPC / protobuf 版本固定；升级时单独提交并跑全量门禁。
- 生成代码（gRPC 桩）只存在于 `build/`，不提交。

## 2. 线程与超时

- **游戏线程不做长活**：登录决策最多 1 个 deadline；遥测全部走队列。
- 所有 gRPC 调用 `.withDeadlineAfter(...)`；没有 deadline 的调用视为 bug。
- 后台线程必须 `setDaemon(true)` 并能在 `close()` 里 2 秒内退出。
- 禁止在事件处理器里 sleep / 自旋 / 无界重试。

## 3. 错误处理

- gRPC 失败统一转 `ControlUnavailableException`，由 `AccessController` 决定 fail-open。
- 业务拒绝（`allowed=false`）是正常路径，不是异常。
- 所有异常必须进日志，不允许 `printStackTrace`、`System.out`。
- 日志里**绝不出现 token**。

## 4. 日志

| 级别 | 用途 |
|---|---|
| INFO | 启动 / 停止、会话开始 / 转服 / 结束、拒绝原因、配置摘要（不含 token） |
| DEBUG | 准入通过、缓存命中（需要时再加） |
| WARN | 队列满、上报失败、控制面不可达 |
| ERROR | 配置无效、插件停用 |

## 5. 测试

- JUnit 5；`test` 必须离线可跑。
- 只在 `ControlGateway` 边界用假实现；配置解析、缓存、会话、队列走真实逻辑。
- 新增行为必须有测试；修 bug 先补能复现的测试。

## 6. 门禁

```bash
./scripts/check.sh
```

1. `spotlessCheck`：google-java-format + SPDX 头；
2. `-Xlint:all -Werror` 编译；
3. `test`；
4. `shadowJar`；
5. proto 与 CCNR-Data 副本一致性（同级检出时）。

CI 跑同一脚本；本地不过 CI 也过不了。

## 7. 提交

- 一个提交只做一件事；消息写"为什么"，不写"改了哪个文件"。
- 改契约单独提交，并在提交信息里注明 CCNR-Data 侧对应提交。
