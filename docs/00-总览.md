# 00 · 总览

## 1. 定位

CCNR-Velocity 是代理侧的 **执行点**，不是第二套业务服务：

- 登录时同步问 CCNR-Data「这个 UUID / 用户名能不能进这个服」；
- 在线期间把会话生命周期报回去，让在线数、时长、登录失败可统计；
- 控制面故障时保护**已在线玩家**，新登录按配置保守处理。

```
LoginEvent ──► AuthorizePlayer ──► allow / deny(reason,message)
                    │
                    └─ 本地缓存 TTL（按 UUID）
ServerConnectedEvent / DisconnectEvent / 定时器
                    │
                    └─► 有界队列 ──► ReportProxyEvent（幂等 request_id）
```

## 2. 边界

| 在插件里 | 不在插件里 |
|---|---|
| 调 gRPC、缓存决策、生成 session_id | 封禁 / 白名单 / 角色规则 |
| 组装事件、异步上报 | 身份绑定、Casdoor 登录 |
| 给玩家可读拒绝消息 | 跨服传送、踢人策略 |

## 3. 失败模式

| 故障 | 行为 |
|---|---|
| CCNR-Data 超时 / 不可达 | 已在线玩家不掉线；新登录 `fail-open=false` 时拒绝并提示 |
| Casdoor 故障（服务端返回 `CASDOOR_UNAVAILABLE`） | 同一次决策直接拒绝；不重试 |
| 遥测队列满 | 丢新事件、WARN 计数；不影响登录与在线 |
| gRPC 慢 | 1 秒 deadline；登录最多多等 1 秒 |
| 插件配置错 | 插件停用并写 ERROR；服务端照常运行 |

## 4. 不变量

- 一个玩家同一时刻只有一条会话；转服不换 `session_id`。
- 心跳只刷新 `last_seen`，不写事件表；因此 100 人在线 ≈ 1.7 次写/秒。
- `request_id` 标识一次事件意图；重试复用同一个，绝不重新生成。
- 任何网络调用都有 deadline；任何队列都有上限。
